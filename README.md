## 🖼️ Project Preview



> **BingePlay Streaming Analytics** is an advanced SQL analytics project that explores user behavior, content performance, subscriptions, engagement, and potential churn patterns for a fictional OTT streaming platform.

---

## 🎯 Project Objective

The goal of this project is to simulate the type of analysis performed by a **Data Analyst in the OTT/Streaming industry**.

Using SQL, the project transforms raw streaming and subscription data into meaningful business insights that can help answer questions such as:

* How much monthly revenue is generated from active subscriptions?
* How is user acquisition changing over time?
* Which devices are used most frequently?
* How do users rate the available content?
* Do original shows perform better than acquired content?
* Which users demonstrate binge-watching behavior?
* Which users signed up but never watched anything?
* Which subscribers may be suitable for plan optimization?
* Which users show potential churn signals?

# 📊 Business Analysis

## 01 — 💰 Revenue Analysis

Analyzed active subscriptions to determine the current subscription base and monthly revenue generated by BingePlay.

**Business Question:**

> How much revenue is currently generated from active subscriptions?

---

## 02 — 📈 User Acquisition

Analyzed monthly signup trends to understand how the user base changed throughout the analysis period.

**Business Question:**

> Is BingePlay's user acquisition growing over time?

---

## 03 — 📱 Device Engagement

Compared streaming activity across different devices.

**Business Question:**

> Which devices are most commonly used for streaming and which have the highest completion rate?

---

## 04 — ⭐ Content Ratings

Analyzed the distribution of user ratings to understand overall content reception.

**Business Question:**

> How satisfied are users with the available content?

---

## 05 — 🎥 Originals vs Acquired Content

Compared original and acquired shows based on their performance and ratings.

**Business Question:**

> Are BingePlay Originals performing better than acquired content?

---

## 06 — 🍿 Binge-Watching Behavior

Identified users and periods demonstrating binge-watching behavior.

**Business Question:**

> Which users are highly engaged with the platform?

---

## 07 — 👤 Inactive Signups

Identified users who registered but never watched any content.

**Business Question:**

> How many newly acquired users fail to start consuming content?

---

## 08 — 💳 Subscription Plan Analysis

Identified subscribers whose viewing behavior may indicate an opportunity for plan optimization.

**Business Question:**

> Are some premium users consuming only lower-tier content?

---

## 09 — 🚀 Upgrade Analysis

Analyzed users who successfully moved from lower-tier plans to higher-tier subscriptions.

**Business Question:**

> How long does it take users to upgrade their subscription?

---

## 10 — 🔄 Cliffhanger Comebacks

Analyzed users who returned to the platform after cliffhanger events.

**Business Question:**

> Can cliffhanger-driven content encourage users to return?

---

## 11 — 📅 Consecutive Engagement

Used advanced SQL techniques to identify users with continuous weekly viewing streaks.

**Business Question:**

> Which users demonstrate long-term engagement?

---

## 12 — ⚠️ Churn Signal Detection

Compared viewing behavior across months to identify users experiencing significant declines in watch time.

**Business Question:**

> Which users may be showing early signs of churn?

# 🚀 How to Run

### 1. Clone the repository

```bash
git clone https://github.com/your-username/BingePlay-SQL-Analytics.git
```

### 2. Open the notebook

```text
bingeplay_sql.ipynb
```

Open it using **Jupyter Notebook** or **JupyterLab**.

### 3. Install dependencies

```bash
pip install pandas pymysql sqlalchemy jupyter
```

### 4. Set up MySQL

Create/import the BingePlay database and configure your database connection.

### 5. Run the notebook

Execute the notebook cells sequentially to reproduce the analysis.

# 🔐 Security Note

Never upload your actual MySQL password to GitHub.

Instead of committing credentials directly into the notebook, use environment variables or a local configuration file that is included in `.gitignore`.

Example:

```python
import os

DB_USER = os.getenv("DB_USER")
DB_PASSWORD = os.getenv("DB_PASSWORD")
```
